# Экспериментальная сортировка MAX

Кнопка `→` в колонках «Не готовы» и «Отсортирован» запускает **только** классификацию выбранного поста. Разметку 3000 обучающих текстов сделал Codex; старые жанровые классификаторы и pipeline обработки здесь не вызываются. На сайте используется TF-IDF baseline из этого эксперимента: на отложенных метках Codex он превзошёл MiniLM. Это не независимая оценка точности.

Результат показывает три широкие категории, все подкатегории внутри каждой из них, шесть обязательных признаков и техническую сложность. Проценты — **некалиброванные оценки модели**, не вероятность истины. Значения разных категорий не обязаны суммироваться до 100%. Цветовые диапазоны только помогают просмотреть оценки. Если лучший широкий score меньше 0,55, карточка получает пометку «Не уверен» и всё равно переходит в «Отсортирован». Пост без текста переходит туда со статусом «Нет текста» без вызова модели.

`POST /api/pipeline/{entry_id}/taxonomy` под существующей Basic Auth принимает только JSON и ставит одну карточку в очередь. Worker запускается отдельно, читает `baseline.joblib` и `taxonomy.json` из `/app/models/max-taxonomy-20260929`, обрабатывает задания по одному, сохраняет оценки и время в `taxonomy_classifications`. API доски возвращает состояние задания; повторное нажатие во время работы ничего не дублирует. При ошибке кнопка доступна для повтора. Если текст изменился, старые оценки становятся устаревшими, а карточка возвращается в «Не готовы».

Таблица `taxonomy_classifications` и миграция `0008` изолированы от прежних `post_classifications`. В таблицу не записывается текст поста: только ID, SHA-256 текста, оценки и состояние. Логи worker не содержат текстов. Рерайт, внешние LLM и публикация остаются выключенными.

На production нужны `TAXONOMY_ENABLED=true`, `TAXONOMY_MODEL_DIR=/app/models/max-taxonomy-20260929` в защищённом `.env`, миграция `alembic upgrade head`, закреплённый образ приложения и запущенный `taxonomy-worker`. Compose ограничивает worker 768 MiB RAM и одним CPU. Каталог с весами не хранится в Git и монтируется worker только для чтения. Перед переключением сохранить тег предыдущего образа и compose; откатить web/worker можно без удаления таблицы и результатов.

Исходный отчёт и корпус хранятся отдельно в защищённом локальном каталоге владельца. Классификатор включён для ручной проверки на production по прямому запросу владельца, несмотря на непрохождение исходного quality gate. Не использовать оценки для автоматической публикации или необратимых решений.
