# Экспериментальная сортировка MAX

На карточке с текстом есть две отдельные стрелки: `→ MiniLM` и `→ TF-IDF`. Каждая запускает только выбранную модель, причём её можно запускать повторно. Во время задания обе кнопки блокируются; при ошибке их можно нажать снова. Пост остаётся в «Не готовы», пока хотя бы одна классификация не завершилась успешно. В «Сравнить прогоны двух моделей» можно выбрать любые сохранённые результаты и увидеть оценки категорий, подкатегорий, признаков и время рядом. То же сравнение доступно на странице поста.

Пост без текста сортируется сразу при импорте, без worker и кнопок. С медиа он получает категорию **«Только медиа»**; без медиа — **«Пустое сообщение»**. Оба случая отделены от смысловой классификации. `python -m app.taxonomy.backfill` один раз переводит ранее скачанные пустые посты в эти статусы; повторный запуск не дублирует строки.

Первый корпус содержал 3000 размеченных Codex текстов MAX. Для второго цикла из той же папки забрали ещё 1000 новых текстов, не встречавшихся в первом корпусе. Codex разметил все 1000; 389 спорных решений (`needs_review`) исключили из обучения. Итого для нового обучения пригодились 2240 текстов: 1629 старых и 611 новых. Ещё 100 новых постов зарезервировали как слепую выборку и не давали моделям при обучении. Их Codex разметил только после фиксации весов.

Вторая проверка 60 меток вслепую дала полное совпадение только в 17 случаях; широкие категории совпали в 35. Поэтому тестовые цифры показывают **согласие с конкретной разметкой Codex**, а не независимую точность. Ни одна оценка в карточке не управляет автоматической публикацией. Проценты — **некалиброванные оценки модели**, не вероятность истины.

На прежних 450 отложенных постах (286 пригодны для метрик) macro-F1 TF-IDF изменился с 0,518 до 0,534, MiniLM — с 0,234 до 0,299. На новых 100 (51 пригоден) TF-IDF изменился с 0,527 до 0,501, MiniLM — с 0,247 до 0,262. У TF-IDF на новых постах выросли micro-F1 с 0,681 до 0,705 и попадание правильной широкой темы в top-3 с 0,906 до 0,931. Эти сдвиги расходятся между метриками; небольшой тест не даёт основания назвать одну новую версию однозначно лучше.

`POST /api/pipeline/{entry_id}/taxonomy/{tfidf|minilm}` под существующей Basic Auth ставит задание. Таблица `taxonomy_classifications` хранит текущий статус по `(pipeline_entry_id, model_key)`, а `taxonomy_runs` — отдельную запись на каждый запуск. `GET /api/pipeline/{entry_id}/taxonomy-runs` возвращает историю по 50 записей с курсором `before_id`. `0009` переводит старые результаты в ключ `tfidf`, старые пустые — в ключ `media`; `0010` переносит доступные на момент миграции результаты в историю как `legacy_snapshot`. Более ранние прогоны, затёртые до `0010`, восстановить нельзя. Текст остаётся только в `telegram_posts`; история хранит его SHA-256, модель, оценки и время. При правке текста старые результаты сохраняются, но помечаются как относящиеся к прежнему тексту. Сравнивать их с новыми следует осторожно.

TF-IDF worker читает `baseline.joblib`, отдельный MiniLM worker — `minilm-v2/epoch-2.safetensors`, локальный tokenizer и config. Оба читают общую `taxonomy.json`. Веса и тексты корпуса лежат вне Git. MiniLM-образ содержит PyTorch; веб и TF-IDF-образ его не загружают. MiniLM ограничена 2 GiB RAM и одним CPU, TF-IDF — 768 MiB и одним CPU. Никакой worker не использует внешние API при inference.

Повторное обучение не запускает постоянный Telegram collector. `python -m app.import_comparison` по защищённому файлу ID и хешей повторно проверяет папку MAX, импортирует только зарезервированные сообщения и не меняет курсор синхронизации. `python -m app.compare_cohort` ставит каждому из них два независимых задания и сохраняет обе истории прогонов. Эти команды нужны для разового сравнения; в обычном режиме новые сообщения сами по себе не подтягиваются.

Скачанные collector файлы хранятся в `telegram_posts.media_path`. Пока обработка выключена, таблица `media_assets` для них не заполняется. Страница `/pipeline/{id}` показывает исходные файлы через защищённый `/source-media/{post_id}`; маршрут проверяет, что файл находится внутри каталога медиа. Изображения и видео выдаются для просмотра, прочие документы — только для скачивания. Если у сообщений совпадают `chat_peer_id` и Telegram `grouped_id`, это части одного альбома: карточки остаются отдельными записями, но показывают общую галерею и ссылку на карточку с текстом. Внешняя ссылка на Telegram ведёт к основной части альбома.

При разовом запуске 29.09.2026 все 100 проверенных постов импортировались из 38 чатов MAX, получили карточки и по одному успешному прогону каждой модели. В каждой карточке остались две записи истории; 39 из 100 постов получили одинаковую первую широкую тему у обеих моделей, 61 — разную. Медиана времени работы на VPS: 33 мс для TF-IDF и 100 мс для MiniLM; p95 — 52 и 322 мс. Это время самого inference в worker, а не ожидание в очереди или загрузка страницы.

На production нужны защищённые `TAXONOMY_ENABLED=true`, `TAXONOMY_MODEL_DIR`, `PUBLISHER_IMAGE` и `PUBLISHER_MINILM_IMAGE`, миграция `alembic upgrade head`, закреплённые образы и оба worker. Compose подключает каталог весов только для чтения. Collector, внешние LLM, рерайт и публикация не включаются этим релизом.
