# Текущая рабочая область

Веб работает с исходными постами MAX, двумя локальными моделями, фильтрами и маркировкой источника.
Collector в рамках этой правки не запускается.

## Экран и код

| Экран / действие | Код | Хранение |
|---|---|---|
| `/dashboard`: стадии, очередь, среднее время и последние прогоны | `app/web/main.py`: `dashboard_data`, `dashboard` | `pipeline_entries`, `taxonomy_classifications`, `taxonomy_runs`, `telegram_sync_state` |
| `/pipeline`: поиск исходного текста, отбор по лейблу/фильтру, четыре рабочие стадии | `app/web/main.py`: `pipeline`; `templates/pipeline.html` | `telegram_posts`, `telegram_chats`, `pipeline_entries`, назначения лейблов |
| `/pipeline/{id}`: оригинал, альбом, панель обработки | `pipeline_detail`, `app/web/source_media.py`, `templates/pipeline_detail.html` | исходный текст и пути скачанного медиа; маркированный текст хранится отдельно |
| Стрелки TF-IDF / MiniLM, блокировка, обновление состояния | `static/pipeline.js`, `app/taxonomy/jobs.py`, `app/taxonomy/worker.py` | текущее задание и отдельная история каждого прогона |
| Сравнение, включая все 38 оценок | `static/taxonomy-compare.js`, `/api/pipeline/{id}/taxonomy-runs` | сохранённые оценки, версия модели, время и отпечаток текста |
| Создание лейблов и редактирование фильтров | `app/web/selection_routes.py`, `static/selection-admin.js` | словарь, версии условий и задания применения |
| Лейблы, причины назначения, снятие и история | `static/post-selection.js`, `app/content/selection_filters.py` | `post_filter_marks`, `filter_evaluations`, `filter_mark_events` |
| «Источник →» | `pipeline_mark_source`, `app/content/source_marking.py` | `marked_text`, `marked_source_url`, `marked_text_sha256`, `marked_at` |

Условия фильтра используют категории, подкатегории и обязательные признаки модели. Назначаемый лейбл — запись, которую владелец создаёт сам в словаре. Это разные сущности.

## Поведение интерфейса

- Доска и карточка используют один опрос состояния раз в пять секунд; скрытая вкладка не опрашивается. Чтение состояния не назначает лейблы и не запускает модель.
- Пока запрос или задание выполняется, кнопки карточки заблокированы. Ошибка видна на карточке; после завершения можно повторить запуск.
- Счётчики доски отражают выборку при загрузке. Смена стадии перемещает видимую карточку; при активном поиске/отборе предлагается обновить выборку.
- Лейблы не снимаются автоматически. Основания и история доступны в панели поста; на доске показываются только компактные лейблы.
- Редактор фильтров сначала показывает предпросмотр. Применение создаёт версию и запускает пересчёт партиями. Фоновое обновление списка не перезаписывает редактируемое правило.
- Обзор — снимок БД. Очередь и последний timestamp синхронизации не считаются доказательством доступности worker или запущенного collector.

## Удалённый веб-контур

Удалены старые страницы, обработчики и шаблоны материалов по ссылкам, старой жанровой классификации, черновиков, рерайта, публикации, старой разметки/моделей, промптов и аудита тем. `ENABLE_PROCESSING=true` больше не возвращает эти маршруты. В текущем вебе нет фонового рерайта и запросов к внешним моделям.

Исторические таблицы и миграции сохранены. Старые автономные инструменты в `app/content` не объявлены удалёнными: в этой правке выведен именно старый веб-контур. Они не вызываются текущими страницами. Удаление исторической схемы и независимых инструментов потребует отдельной проверки их потребителей.

## Проверка и выпуск

`python -m pytest` проверяет очереди, модели, условия и старые вспомогательные функции. Интеграционные тесты требуют `FILTER_TEST_DSN` с именем БД, начинающимся на `publisher_filter_qa`: используют только отдельную расходную БД. Проверяются обе модели, несколько фильтров, ручное снятие, сохранение маркировки, закрытые страницы, актуальные экраны и исключение чужих папок.

Образы собираются в GitHub Actions после тестов. Развёртывание использует digest обоих образов, сохраняет предыдущую конфигурацию и проверяет web/worker health. Изменений схемы для очистки интерфейса нет; исходные данные не удаляются. Проверка экранов выполняется в браузере на QA и после переключения production.
